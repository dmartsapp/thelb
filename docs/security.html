Security

How to check a release, what theLB trusts by design, and how to report a vulnerability.

Report a vulnerability#

Please report it privately, through GitHub: the repository's Security tab, Report a vulnerability. Do not open a public issue for it.

Say what you found, which version (thelb --version), and how to reproduce it. You will hear back within a week. The fix goes into a patch release of every supported line, and the advisory is published with it, crediting you unless you ask otherwise.

VersionSupported
0.1.xyes

Before 1.0, only the latest minor line gets fixes.

Check a release#

Every release has, for each binary:

FileWhat it is
thelb-<version>-linux-<arch>the binary
....sha256its SHA-256 checksum; SHA256SUMS has all three
....cdx.json, ....spdx.jsonits software bill of materials (SBOM), CycloneDX 1.6 and SPDX 2.3: the Go release and every module it was built from

And GitHub-signed attestations: one saying which workflow built the binary from which commit (build provenance), and one for each SBOM.

Shell
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify thelb-0.1.0-alpha.3-linux-amd64 --repo dmartsapp/thelb
gh attestation verify thelb-0.1.0-alpha.3-linux-amd64 --repo dmartsapp/thelb --predicate-type https://cyclonedx.org/bom
gh attestation verify thelb-0.1.0-alpha.3-linux-amd64 --repo dmartsapp/thelb --predicate-type https://spdx.dev/Document/v2.3

The SBOMs list exactly what is inside the binary, so you can check it against vulnerability databases with your own tools.

What theLB trusts, by design#

These are not vulnerabilities, but you should run theLB with them in mind.

  • The directors' network. VIPs move by ARP and neighbour discovery, which anyone on the network can answer. IPVS connection sync - multicast to 224.0.0.81, UDP 8848 - is not authenticated by the kernel: a machine on that network can inject connection entries. Keep the directors on a network that only they and their backends share.
  • The secret files. A secret lets a machine ask to join; it never lets one in by itself - every new node waits for approval. Keep the files owned by root, mode 0600 (theLB refuses others). After a leak, see If a secret leaks.
  • Root on the nodes. theLB runs as root, with only the capabilities it needs under the unit thelb generate systemd prints. Anyone with root on a director can act as that director.
  • The metrics endpoint is plain HTTP without authentication. Give --metrics an address only your monitoring reaches.
  • Kubeconfig files. A kubeconfig says which server to talk to and which files to send it. Like kubectl, theLB trusts the kubeconfig you give it: use only kubeconfigs from people you trust. theLB refuses to send one of its own secrets as a token.

What theLB checks#

theLB checks what it is given where it comes in, and quotes or cleans it where it goes out. Nothing it is given can add a command to a script, a line to a unit or a log, or an escape sequence to your terminal.

What comes inWhat theLB checks
Command-line argumentsBefore any command reads them: UTF-8, no control characters (newlines, terminal escapes), no characters that reorder text, at most 4096 bytes. Names, addresses, ports and interface names are checked for what they are.
Another node's messagesA joining node's name, address, MAC address, fingerprint, hostname, version and member identity; a backend's offers (name, protocol, port, check), heartbeats (at most 4096 VIPs and checks) and version; every message is at most 1 MiB. A backend checks the leader's orders before it changes the kernel.
The Kubernetes APIEach Service, Node and EndpointSlice: names, namespaces, ports, protocols, policies. An object an API server would never send is left out, and the director logs a Kubernetes object left out. theLB's annotations are checked before use: at most two pools and addresses, and a shared-VIP key like a label's value.
FilesSecret files: owned by root, mode 0600, a regular file. Kubeconfigs and the files they name: regular files, at most 1 MiB, nested at most 32 deep; tokens are printable ASCII without spaces, at most 16 KiB.
Health checksAn HTTP check's path: printable ASCII from /, at most 512 characters.
What goes outHow theLB makes it safe
generate commandsEvery value from the cluster's state is one shell word, quoted where needed.
generate systemdArguments quoted as systemd reads them; % and $ escaped.
generate k8sWhat the cluster says is checked before it goes into a file or a script; strings in YAML are quoted.
LogsValues with spaces, quotes or anything not printable are quoted, with the characters escaped.
status, doctor, errorsControl characters shown as ?.
MetricsLabel values escaped as Prometheus reads them.

What is in scope#

theLB's own code: the cluster's protocol (mutual TLS 1.3, the join proof, approvals, certificates, revocation), the local socket's authorisation, how secrets are read and kept out of logs, the kernel state it writes, and the metrics endpoint.

The same policy is in the repository's SECURITY.md.
